# 通用写作规则

在从零写完整稿、重构或实质性改写前读取本文件。它规定主线、事实边界和叙事基调；具体 Hook、标题、节奏和口语规则见 [钩子与口语节奏](hook-and-oral-rhythm.md)。

## 1. 一稿一刀口

- 让一条口播稿只服务一个核心认知翻转。多个论点是素材池，不是必须覆盖的清单。
- 把视频视为注意力旅程，不是信息罗列。每段都要让观众获得新判断、证据、推进或问题。
- 用“这条视频只想让谁明白什么”概括主线。若只能概括成“讲 A、B、C”，继续砍掉支线。
- 选择主线时依次检查：是否反常识、是否与观众近期场景直接相关、是否提供非替代性的理解。

## 2. 动笔前审核素材

1. 通读全部材料，建立论点树：主张、前提、证据、案例、反例和结论。
2. 标记三类可用资产：核心洞察、精彩案例或故事、可核实的数据或事实。
3. 列出信息缺口：逻辑跳跃、缺少背景、无法核实的结论，以及可能被误读的因果关系。
4. 核实人名、产品名、公司名、技术术语的准确写法；需要口播英文时一并确认发音。
5. 发现证据不足时，补充可核实来源、降级为个人经验或假设场景，或删除精确断言。

不要因论点树包含某项就强行写入。支撑不了主线的内容可以舍弃。

## 3. 结构义务

按内容类型选择主结构，但让观众在完整叙事中获得以下四类信息：

1. 从核心矛盾、真实场景或结论进入，说明问题为何重要。
2. 解释底层逻辑或关键证据，不停在表面现象。
3. 给出方法、判断标准或下一步，不让观众只带走焦虑。
4. 收束常见误区或适用边界，回到开头承诺。

并非每条短视频都要平均展开四层；短视频优先一个完整判断和可兑现价值，长视频再分章推进。

## 4. 事实、案例与术语

- 优先使用用户提供的真实材料，其次使用可核实的公开案例、数据、研究或权威观点。
- 把来源、样本范围、结论和适用条件拆开说；不要把相关性写成因果，也不要把解释性算例伪装成实测结论。
- 首次出现关键技术术语时，保留英文原词并给出自然的中文说明；后续可用中文简称。不要只用音译或难以检索的意译替代原词。
- 让术语、案例与结论彼此对应。一个术语无法解释时，先给场景或机制，再给名称。

## 5. 叙事基调

- 以“观众的理解框架发生变化”为核心收益，不以恐惧驱动观看。
- 将“慌了、淘汰、崩塌、毁灭、噩梦、灾难性后果”改为可核实的结构变化、具体代价、约束或风险。
- 用情绪承载真实冲突，不用过度修辞遮盖证据不足。
- 结尾避免“令人深思”“太震撼了”一类空洞升华；交付可操作的判断、方法、边界或下一步。

## 6. 冲突处理

- “具体”不等于捏造细节。没有真实场景时，明确标注为假设场景。
- “有情绪”不等于制造焦虑。情绪应来自事实、故事和真实后果。
- “留悬念”不等于隐藏主题。开头必须让目标观众知道这和自己有什么关系。
- “信息密度高”不等于概念堆叠。优先删去不能推动主线的内容。
