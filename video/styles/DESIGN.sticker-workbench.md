# 奶油纸面贴纸工作台（Sticker Workbench）

> 适用内容：面向中文 AI、自动化、产品方法论与工具解释的横屏知识视频。
>
> 画幅与帧率：`1920 × 1080`、16:9、`30 fps`。

本文件固定一种“贴在极淡暖灰画布上的可动解释板”风格：**大面积留白 + 深碳灰粗描边 + 有重量的硬投影 + 低饱和莫兰迪纸片组件**。它适合把抽象的 Agent、提示词、流程、决策和数据关系，转为一眼看懂的实体对象。

它不是 UI 还原规范。项目专属的色彩叙事、关系拓扑、逐 cue 节拍和验收写入项目视觉适配合约；`video-spec.md` 保留镜头事实与叙事规格；真实截图仍按事实素材处理。

## 1. 使用边界

- 默认适用：中文技术讲解、AI Agent 机制、自动化流程、产品概念与方法论；横屏 `1920 × 1080`。
- 核心感受：像一张被整理过的纸面工作台，而不是 SaaS 仪表盘、PPT 或赛博 HUD。
- 每镜命题：用 1–3 个显性物件讲完一个关系，例如“问题卡 → 处理窗口”、“三个角色 → 一个流程”、“输入 → 判断 → 输出”。
- 允许覆盖：已确认的项目 logo、经授权的真实素材、品牌名、实际字体文件；真实录屏可以放入“窗口”容器，但不得被重绘成假界面。
- 不允许覆盖：极淡暖灰大底、深碳灰粗描边、硬投影、充足留白、颜色按层级与状态分配的规则、字幕安全区和真实性规则。
- 项目开工确认：实际可嵌入字体、是否出现真实录屏、是否有品牌色替换、是否需要字幕，以及“彩色卡片代表中心/并列关系，还是代表真实独立对象”。
- 非 16:9 项目不得直接缩小本布局；可保留色彩、描边和组件语法，但应为该画幅新建派生规范。

## 2. 设计 Token

| Token | 值 | 固定语义 |
| --- | --- | --- |
| Canvas | `#FAF8F5` | 全片静止的极淡暖灰纸面；避免暖黄脏感、纯白与偏蓝冷灰 |
| Paper | `#F4F4F6` | 标签、窗口 chrome、真实窗口与非语义结构容器的浅灰纸面；不默认承载命题 |
| Ink | `#282727` | 文字、描边、关系线、图标；深碳灰而非纯黑 |
| Ink Soft | `#5D5A58` | 次级说明、非焦点图形 |
| Line Soft | `#B7B2AC` | 非关键引线、低优先级分隔与虚线 |
| Core Blue | `#BED4F4` | 每一叙述拍唯一的中心命题、主步骤或处理节点 |
| Blue | `#DDE9F8` | 同一层级、同一类型的并列对象与普通信息节点 |
| Pink | `#FCE4EC` | 已明确为创作者、人工决定或第二真实阵营的独立对象；不得只为做对比而添加 |
| Orange | `#F5D8AB` | 风险、错误、反例、缺失与待判断；并列节点场景中优先作为小状态标记 |
| Mint | `#D1E7DD` | 已接通、已确认、当前动作与连接焦点；只作小面积状态标记 |
| Violet | `#E8DEF8` | 声音来源、候选素材或第三真实独立对象；不能当通过/失败状态色 |
| Shadow | `#454342` | 所有硬投影；保持单一深灰色值，不能改为模糊阴影 |

### 颜色纪律

- Canvas、Paper、Ink 是每镜的固定底层；彩色只落在有叙事职责的组件上，不给普通容器“上色”。
- **先定层级，再定状态**：一拍中只有一个中心命题/主步骤可使用 Core Blue；属于同一集合、同一流程层或同一信息层的并列卡统一使用 Blue。不能因为卡片文字不同，就给每张并列卡换一种颜色。
- Pink 与 Violet 只表示已被旁白声明为不同的真实角色、来源或阵营；若只是同一对象在不同位置、同一种声音或同一级结果，必须使用同色。
- Orange 与 Mint 是状态色，不是默认的大卡片色。风险、错误、反例与确认应优先用圆点、短标签或局部标记表达；只有整镜都在讲风险或整张卡本身就是反例时，才可把 Orange 铺满卡片。Mint 永远不表示“已经配过音”，只表示当前关系已接通或条件已确认。
- **容器语义**：承载中心命题的卡使用 Core Blue；承载同级对象、规则、输入、输出或结论集合的卡使用 Blue；人工决定、真实第二阵营、声音来源等有独立事实身份的对象才使用 Pink 或 Violet；风险类对象才使用 Orange。不能因为还没有安排颜色，就退回成纯白底黑字。
- **Paper 边界**：Paper 只保留给真实截图/文档的外框、字幕底板、章节编号、无语义的窗口 chrome、短标签和短代码样例。若一个 Paper 容器本身读得出命题或对象，就必须改为层级色或真实对象色；若它是事实素材，才可因保留原貌继续使用 Paper。
- 一镜通常使用 1 个 Core Blue 主物件、1 组 Blue 并列对象和最多 1 个真实独立对象色。状态色只占小面积，不能产生多个抢眼大色块。
- 没有“彩色描边”系统：彩色组件一律用 Ink 描边和 Shadow 硬投影；普通 Paper 面板用 Ink 描边即可。
- 不使用渐变、透明玻璃、发光、霓虹、金属高光或把颜色仅当氛围的暗色背景。

## 3. 字体与文字层级

实际渲染必须嵌入字体；若无字体文件，使用以下明确 fallback。中文以清晰厚重的无衬线为主，英文短词可更圆润，但不能抢过中文命题。

| 用途 | 字体 | 字重 | 字号 | 行高 | 规则 |
| --- | --- | --- | --- | --- | --- |
| 主命题 | `Noto Sans SC`, `PingFang SC`, sans-serif | 900 | 72px | 1.12 | 1–2 行；Ink；左对齐或置于窗口中央；只强调一个词组 |
| 大数字 / 大问号 | `Fredoka`, `Noto Sans SC`, sans-serif | 800 | 92px | 0.95 | 只放一个核心数字、符号或极短英文词 |
| 卡片标题 / 关键词 / 结果 | `Noto Sans SC`, `PingFang SC`, sans-serif | 800 | 40px | 1.15 | 适合对象名、流程节点、结论和必须一眼读懂的短词 |
| 正文 / 说明 | `Noto Sans SC`, `PingFang SC`, sans-serif | 700 | 30px | 1.35 | 每张卡最多 2–3 条；不用密集段落 |
| 中文短标签 | `Noto Sans SC`, `PingFang SC`, sans-serif | 800 | 28px | 1.10 | 用于卡片顶部的分类、问题和状态；它仍是知识内容，不得伪装成 UI 微文案 |
| 英文短标签 / 窗口 chrome | `IBM Plex Mono`, `JetBrains Mono`, monospace | 700 | 20–22px | 1.00 | 只用于短标签、代码或窗口 chrome；不超过中文主标题的 60% 视觉强度 |
| 编号 / 元数据 | `IBM Plex Mono`, `JetBrains Mono`, monospace | 700 | 20px | 1.00 | 只放章节号、时间码、版本或不影响理解的极短流程号 |
| 字幕 | `Noto Sans SC`, `PingFang SC`, sans-serif | 750 | 32px | 1.28 | 居中；Ink 字配 Paper 底板；每条至多一个与当前可见对象对应的关键词使用其可访问文字色 |

- 中文主标题不用花体、斜体、描边字或“逐字弹出”；它负责迅速读懂。
- 英文事件码、文件名和短代码是元数据：字号通常为 `20–22px`，可降至约 `60%` 不透明度，不能与中文对象名争夺主层级。
- 英文短词可使用圆润粗体制造玩具感，但不用任何字体模拟手写涂鸦。
- 中文语义文字（对象名、问题、规则、输入、输出、风险、结果）不得使用“英文短标签 / 窗口 chrome”或“编号 / 元数据”层级；卡片内最小使用“正文 / 说明”层级。
- 不使用负字距。文案过长时先改写为短命题、扩大卡片或拆成两层卡片，不以缩小字号、压缩字距补救。
- 播放验收以 `1920 × 1080` 成片的常规预览大小为准：观众应在 `2s` 内读出所有语义文字；读不出时先删减或放大，不能降级为 UI 微文案。
- 强调优先采用色块、贴纸标签或组件位置变化；同一句不同时使用加粗、彩色、下划线、描边和放大。

## 4. 画布、留白与字幕安全区

| 区域 | 固定值 | 用途 |
| --- | --- | --- |
| 外框 | `10px` Ink | 全片四周的可见印刷边框；内容不得与其相撞 |
| 内容左右安全边距 | `120px` | 主命题、物件、流程线的最小边距 |
| 顶部安全边距 | `74px` | 贴纸角标、窗口标题栏与标题起点 |
| 内容底部预留 | `168px` | 主关系、结论和真实素材不得进入 |
| 主体留白目标 | 不少于画面 `35%` | 让 1–3 个贴纸物件有呼吸感，不排成满屏 UI |
| 组件间最小间距 | `44px` | 关系线与硬投影不会相撞 |
| 窗口 / 文档圆角 | `10px` | 仅用于大 Paper 容器；不做胶囊化界面 |
| 贴纸圆角 | `8px` | 小色块和便签；大问号卡可到 `18px` |
| 标准描边 | `4px` Ink | 面板、贴纸、角色卡、流程节点与图标 |
| 标准硬投影 | `8px 8px 0 #454342` | 只向右下投射；不可模糊、不可半透明 |
| 字幕左右边距 | `260px` | 留出左、右叙事物件和硬投影 |
| 字幕底距 | `42px` | 字幕稳定在外框之上 |
| 字幕最小高度 | `76px` | Paper 底板；最多两行 |

- 大多数镜头采用不对称的左右双主体：左侧是“问题 / 输入 / 人”，右侧是“系统 / 结果 / 方案”；它们之间用一根明确关系线连接。
- 单一主物件可居中，但应配合角标、小贴纸或轨迹，避免落成空白 PPT。
- 全片可固定外框，禁止每镜出现不同的背景、满屏边栏或网页导航。
- 用 flex、grid、锚点和具名组件推导布局；避免把每张贴纸堆成无语义的绝对坐标。
- 字幕轨是最后的阅读层。任何底部卡片、流程终点、角色脚部或注释都必须让开它。

### 4.1 字幕轨执行合同

以下数值是横屏 `1920 × 1080` 成片的实现值，不是可凭视觉自由调整的参考值：

- 字幕卡外边界固定为 `left/right: 260px`、`bottom: 42px`、`min-height: 76px`；使用 `4px` Ink 描边、`8px` 圆角、`8px 8px 0 #454342` 硬投影和不透明 Paper 底板。单行卡不得因字体或过大内边距高于 `76px`。
- 字幕文字固定为 `32px / 750 / 1.28`，水平居中，内边距为上下 `8px`、左右 `24px`。一条 cue 最多两行；若会出现第三行，必须在旁白自然停顿处拆分 cue，不能缩小字号、压缩字距或裁切文本。
- 两行字幕卡的最高边界约为 `y=932px`，连同硬投影占用底部阅读带。所有场景对象、连线、标签和硬投影的最低像素必须止于 `y=912px`，至少留出 `20px` 间隔；不能把“说明条”或结论卡垫在字幕后面。
- 每条字幕可有 **0 或 1 个** 高亮短词。只有该词与同一时刻画面中可见的对象、风险或已完成动作直接对应时才高亮；对象未出现、颜色含义不唯一或句子只是过渡说明时，保持 Ink。不得用颜色替代语义判断，也不得整句上色。
- 高亮必须只改变文字颜色，不能同时加粗、放大、下划线、描边、色块或逐词动画；整句仍按 cue 的开始和结束一次显示。Core Blue/Blue/Pink/Orange/Mint/Violet 的原始 Token 是卡片底色，字幕文字使用同色相、满足 WCAG AA 大字对比度的深色文字变体，避免浅 Mint、Orange 或 Violet 在 Paper 上失读。

## 5. 固定画面语法

### 5.1 三层画面

1. **背景**：Canvas 纯色 + Ink 外框。默认静止、无网格、无渐变、无粒子、无环境光。
2. **主体**：1 个完整的“纸面论证”。主体可以是窗口、文档、问号卡、角色卡、流程节点、徽章或环形关系，但必须读得出对象之间的因果或归属。
3. **前景**：极少量短标签、Mint 提示、路径箭头、小星形或编号。前景用于引导视线，不能盖住主体文字。

### 5.2 基础组件

| 组件 | 构造与用途 | 禁止用法 |
| --- | --- | --- |
| 浏览器 / 文档窗口 | Paper 底、4px Ink 描边、10px 圆角、8px 硬投影；可有 Core Blue/Blue 标题条和 2–3 个同色中性圆点。装真实工具画面或抽象规则。 | 伪造真实产品的 UI、堆满输入框、把整镜做成后台界面。 |
| 便签 / 贴纸标签 | Core Blue、Blue、Pink、Orange、Mint 或 Violet 实底；4px Ink 描边；8px 圆角。大多数保持水平，只有短贴纸可轻微旋转 `-2°` 至 `2°`。用作短问题、判定、注释。 | 用来承载段落、每个元素都旋转、叠成不可读的装饰墙。 |
| 问题卡 | Orange 的竖向卡片，中心只放大问号、眼睛、感叹号或 1 个短问题。用于“未知 / 待判断”。 | 同时放大问号、长标题、列表和多个图标。 |
| 角色卡 | Core Blue、Blue、Pink 或 Violet 的圆角矩形或小方块；同组角色统一一种色，只有真实不同身份才换色。可有极简表情、眼镜、徽章和短名称。 | 人物照片、3D 角色、复杂肢体、无关的可爱装饰。 |
| 流程节点 | 纸片、窗口或角色卡只可通过 5.2.1 规定的关系线相连；线条只说明方向或关系。 | 无箭头含义的蜘蛛网、细灰线、复杂 BPMN 图。 |
| 结果章 / 徽章 | Mint 小标签、圆形印章或低矮贴纸。只在判断完成时出现。 | 每张卡都加“成功”章，或用它替代结论。 |

### 5.2.1 关系线约束（强制）

关系线是用来读懂因果、流程、归属或坐标的**关系层**，不是装饰。全片只能使用以下两套语法；同一条关系不得临时改色、加粗、换箭头或改成第三种样式。

| 关系类型 | 视觉语法 | 使用边界 |
| --- | --- | --- |
| 流程 / 因果 | `4px` Ink 实线 + 单个小型 Ink 实心箭头 | 只用于有明确先后或流向的关系，例如输入→判断→输出、问题→解决、角色→处理器。 |
| 坐标 / 对照 / 定位 | `4px` Ink 主轴 + `3px` Line Soft 虚线辅助轴；默认无箭头 | 只用于对照、坐标、辅助定位或解释真实素材的短引线。若没有方向含义，禁止添加箭头。 |

- **颜色纪律**：Mint 只用于“已接通 / 已确认”的连接焦点或节点，Orange 只用于风险路径所连接的对象；两者不能制造新的线型、彩色箭头或整段彩线。
- **图层纪律**：关系线永久位于卡片、节点、文字、标签和硬投影之下；它可以经过画布留白，但不得穿入卡片、遮住文字、被硬投影截断，或看起来像断线。
- **端点纪律**：线的起点和终点停在节点 Ink 描边外的留白中，与描边和硬投影至少留出 `8px` 安全间隙。先通过锚点、路径转折或调整组件位置解决冲突，不能把端点插进卡片、文字区或投影中。
- **箭头纪律**：在 `1920px` 画布上，箭头使用固定小尺寸，不随线宽或节点大小放大。SVG 推荐 `markerUnits="userSpaceOnUse"`、`16 × 16` marker、约 `14px` 的实心三角；每条流程线最多一个终点箭头。
- **时序纪律**：源节点与目标节点必须先清晰可见；目标节点完成落位后，才沿阅读方向绘制该段关系线，最后才弹出 Mint 连接焦点。不能因关系线容器提前进入，让后续箭头先于内容出现。
- **SVG 实现纪律**：初始 DOM 禁止写 `marker-end`。路径开始绘制的同一时间点才设置 `marker-end`（例如 GSAP 的同一时间点 `.set()`）；这样即使路径用 `strokeDashoffset` 隐藏，也不会留下悬空箭头。

### 5.2.2 关系拓扑先于布局

纸面工作台的活力来自有主次的不规则纸片，但纸片位置必须由关系决定，不能由视觉均衡倒推关系。

- 先声明节点、关系方向、边的语义与最终判断，再决定卡片落在画布的哪一格；不能把“左右对称”或“留白好看”误当成关系结构。
- 等权的 hub-and-spoke（一个中心窗口被多张角色卡或卫星贴纸围绕）应两侧均衡展开；若必须不对称，项目视觉适配合约必须声明信息层级或阅读顺序的理由，例如“左重右轻是因为右侧是输出”。
- 每条流程线必须从语义源节点的 Ink 描边外缘出发，并准确接到目标节点的描边外缘；不得穿过卡片文字、悬空停在节点旁，或以无语义短碎线代替关系。
- decision fork（一次判断分出多条分支）的回路、风险或纠正说明必须归属对应分支，不能漂在分支之间的留白里造成归因不明；回路应沿原路径返回，不应另起一条新线型。
- 线、节点和路径说明不得互相遮挡；当引线、标签和硬投影相撞时，先调整组件位置或路径转折，不能靠压低 z-index 把线藏进投影。

### 5.3 构图模式

- **问题 → 解决**：Orange 问题卡在左，Blue 解决窗口在右；中间由 Mint 点或箭头接通。
- **多角色协作**：最多 3 张角色卡半覆盖地围绕一个窗口或中心节点；每张仅保留名称、色彩与一项职责。
- **输入 → 判断 → 输出**：三个大小不完全相同的纸片沿一条明确路径排布；中间“判断”最大，输出用彩色贴纸锁定。
- **对照**：左、右两张不同色的同类卡片隔开足够空白，中间放一个小问号、眼睛或短连接词；不用传统表格。
- **概念展开**：中心大窗口 + 2 个轻微倾斜的卫星贴纸；卫星物件位于中心物件外缘，不与正文重叠。

### 5.4 焦点纪律

- 每镜只有一个需要立即读懂的“主物件”；另外 1–2 个物件只帮助解释关系。
- 同一叙述拍只有一个主要焦点变化：色变、缩放、旋转或位置变化四选一；跨 cue 的顺序状态变化允许，但每一步都必须回指已声明的音画节拍，不能在一句旁白里同时触发两个物件的色变或两个贴纸的回弹。
- 角标、标题条、小星形、Mint 点属于引导线索，不能与主物件争夺面积或饱和度。
- 不连续两镜沿用同一套“双卡并排”构图；当关系从问题变成流程或对照时，主体结构也应改变。

## 6. 真实素材规则

真实录屏、截图和用户素材是事实层；本风格只给它们一个“纸面窗口”，不重画或美化成虚构界面。

- 真实素材放入 Paper 窗口时，保留可辨识的原始文字、数据、时间、状态和操作结果。
- 可在窗口外添加 1 个彩色贴纸标签、1 条短引线或 1 个 Mint 提示点，解释旁白正在说的真实区域。
- 录屏内的原始 UI 配色不必被强行改成 Blue/Pink/Orange；贴纸风格只存在于外层框架。
- 坐标未核对时不画大红框。优先使用边缘标签、短引线或“此处需要确认”的 Orange 问题卡。
- 禁止伪造窗口内容、改写真实数据、添加不存在的成功提示、遮挡关键操作或把原视频水印/频道标识迁移到新项目。

## 7. 动效语言

动效应像把纸片依次贴到桌面上：**有弹性、有方向、停下后稳定**。静态背景不参与环境动效；动效只发生在阅读顺序与关系建立的位置。

| 对象 | 默认进入 | 强调 | 终态 |
| --- | --- | --- | --- |
| Ink 外框 / 固定小角标 | `0.18s` 淡入 | 无 | 全镜稳定 |
| 主窗口 / 主卡 | `0.34s` 从叙事方向平移 `40–64px`，同时由 `0.86` 弹至 `1` | 一次轻微 `1.00 → 1.035 → 1.00` | 保持水平、稳定可读 |
| 倾斜贴纸 | `0.28s` 从 `0.76` 缩放并回弹，常规卡最终落在 `-1°..1°`，短贴纸才可落在 `-2°..2°` | 仅一次 `2°` 摇摆或局部放大 | 停止，不持续抖动 |
| 角色卡 | `0.30s` 从下方或侧方跃入 | 眼镜、标签或表情可延迟 `0.10s` 出现 | 保持，不能持续跳动 |
| 流程线 / 虚线轨迹 | 在关联节点落位后，用 `0.42–0.56s` 沿阅读方向绘制 | Mint 连接点在接通时弹出 | 保持完整关系 |
| Mint 提示 / 结果章 | `0.20–0.26s` 快速弹入 | 一次 `1.12 → 1.00` 锁定 | 保持到结论读完 |
| 章节转场 | `0.18–0.28s` 快速淡化或硬切后重组 | 仅在观点反转、风险警告时硬切 | 不做整页翻转 |
| 最终结论 | `0.42s` 主结论卡落位，辅助贴纸后入 | Mint 徽章最后锁定 | 停留至少 `1.2s` 后淡出 |

- 动效只配合“所以、但是、交给、判断、完成”等关系词或句末重音，普通解释不逐句飞入。
- 主要对象的进入方向要体现因果：输入从左/上进入，处理器居中落位，输出向右/下出现；不要每个元素都从下方弹入。
- 使用有界的弹性曲线，例如 `cubic-bezier(.34, 1.56, .64, 1)`；不可使用长时间果冻、无休止悬浮、随机抖动或转圈。
- 相邻镜头应保留一个视觉锚点（外框、某个对象色或同一窗口语法），再替换主体关系；避免用炫目的转场代替叙事。

### 7.1 音画同义与证据纪律

本风格服务的是把旁白关系变成一眼看懂的实体对象，不是把每句旁白都贴成一张会动的纸。每个可见物件都必须能回指到当前或已保留的旁白落点；字幕、屏显和物件状态描述同一个命题时，三者不得互相补充出不同的事实。

- 屏显术语、数字、对象名和结论必须由当前 cue 或已经成立且仍在画面的 cue 引入。后续章节才会解释的概念、数量、模板结构或因果结论不得提前出现；真正的预告必须标为“预告”，并在项目视觉适配合约写明理由。
- 同一对象跨画面、字幕高亮与屏显文案必须使用同一名称和同一语义色。例如字幕中的风险词与画面中的 Orange 问题卡都使用 Orange 语义；不得让字幕说“问题”、画面却把同一对象渲染成 Mint 已确认。
- Hook、章节与最终结论可以使用大字或大问号卡；机制解释必须展示对象、关系或状态变化。只有大标题、装饰性纸片墙、未被旁白指向的附加便签，都不构成讲解。
- 关键机制在项目视觉适配合约中声明证据类型：关系图、经过核对的真实文本摘录、真实录屏或已核对的素材。程序化纸面图只能解释已知事实，不能伪造产品界面、执行结果、数据或来源；真实素材仍按第 6 节处理。
- 一个完整句子默认只触发一个主要可见动作；动作发生在关系词或句末重音之后。最终状态必须比动效本身更易读，并保留足够的 HOLD，不能让纸片还在回弹时旁白已经讲完。
- 实现前冻结逐 cue 的“旁白命题 -> 屏显物件/文案 -> 字幕锚点 -> 动作 -> 终态”契约。实现后，任何一处文字或时间修改都必须同步回写该契约，不能只改 HTML 或只改分镜。

### 7.2 命名动效动词

下列动词是 sticker 风格对纸片动作的命名封装，与第 7 节的对象表格配套使用：对象表格规定“怎么动”，动词规定“为什么动”。同一动作不得同时承担两个动词的语义。

| 动词 | 可复用语义 | sticker 最低实现要求 |
| --- | --- | --- |
| SLAM | 命题或主物件落位 | 主窗口/主卡从叙事方向平移并回弹至清晰终态，不以普通淡入替代。 |
| CASCADE | 同类物件按叙述顺序建立 | 多张角色卡或卫星贴纸方向一致、间隔可感知地依次落位，每张完成后保持可读。 |
| LOCK | 已成立的焦点被锁定 | Mint 徽章或结果章单次弹入锁定，不重复抢焦点。 |
| CONNECT | 源物件与目标物件的关系建立 | 流程线沿阅读方向绘制，Mint 连接点在接通时弹出，路径方向与语义方向一致。 |
| CHECK | 已通过的条件或核对点 | Mint 提示点单次轻量弹入，终态清楚但不与结论竞争。 |
| FLAG | 风险、错误或反例被指出 | Orange 问题卡或便签即时可读地落位，不以装饰性抖动替代。 |
| DIM | 非焦点物件后退 | 降低非焦点纸片的对比度，但不把仍有解释价值的物件变成不可读；等级见 7.3。 |
| RESOLVE | 判断后的可执行解法成立 | 先以 Blue 方案卡落位，再由 Mint 徽章标记已成立；覆盖层或色变不得遮住文字。 |
| HOLD | 已得出的结论被保留 | timeline 尾部保留可读终态，不能以转场代替结论。 |
| FADE OUT | 画面完成后的退出 | 只在没有仍需阅读的关系或结论时发生。 |

### 7.3 DIM 可读性等级

sticker 风格以纸片为物件单位，DIM 主要用于让非焦点纸片后退，让当前叙述拍的 Mint 焦点或新落位的主物件更突出。项目视觉适配合约必须为每个 DIM 事件声明等级、对象、触发 cue 与终态。

| 等级 | 建议下限 | 适用边界 |
| --- | --- | --- |
| 轻 DIM | `opacity >= 0.70`、`brightness >= 0.88` | 对照物件仍需被观众逐字阅读，只降低其与当前焦点的竞争。 |
| 中 DIM | `opacity >= 0.55`、`brightness >= 0.78` | 物件仍保留解释价值，但已不再是当前叙述拍的主要焦点。 |
| 强 DIM | `0.40 <= opacity < 0.55`、`0.65 <= brightness < 0.78` | 仅用于已无需阅读的冗余纸片；仍承载风险、条件、分支说明或结论的物件不得使用。 |

- 任何仍有解释价值的纸片不得强 DIM；需在最终关键帧阅读的文字至少使用中 DIM，且必须人工确认可读。
- 若 DIM 后纸片仍承担比较关系，应保留其语义色、Ink 描边和可辨识文字，不能以透明度归零代替退出，也不能把硬投影一起抹掉让它“消失”。
- Mint 成为解决焦点不等于其他事实失效；DIM 只改变焦点层级，不改写事实语义。Orange 问题卡被 DIM 后仍是问题，不能让观众误以为它已解决。

## 8. 禁止项

- 纯白、纯黑、冷灰或全屏渐变背景；扫描线、网格、粒子、镜面反射、霓虹发光、玻璃拟态、毛玻璃和 3D。
- 细描边、柔焦阴影、低对比灰字、无边框扁平卡片、规则的等宽卡片网格、满屏 dashboard。
- 照片人物、写实机器人、复杂插画、无关 B-roll、仅为填满留白的图标雨。
- 假网页、假录屏、假评论、伪造指标、原参考视频的频道 logo、水印、角色命名、原片文案或界面截图。
- 每句话一个弹窗、逐字打字机、全元素同方向飞入、持续摇摆、全屏翻页、故意制造眩晕的缩放。
- 把所有彩色组件做成相同大小、相同角度、相同权重；本风格的活力来自有主次的不规则纸片，而不是杂乱。

## 9. 项目验收

- [ ] 画布为 Canvas 极淡暖灰，四周 Ink 外框存在；背景没有渐变、纹理、发光或无意义装饰。
- [ ] 所有纸片/窗口使用近黑 `4px` 描边和同向、不模糊的硬投影；没有柔和投影或彩色描边。
- [ ] 每镜只有一个 Core Blue 主物件，Blue 并列节点保持同色，彩色大色块不超过叙事所需数量，Mint 只表示当前动作或确认。
- [ ] 至少保留约 `35%` 的有意留白；主体、硬投影与结论均避开字幕安全区。
- [ ] 字幕卡严格使用 `260px / 42px / 76px / 32px / 750 / 1.28` 合同；两行卡不超过 `y=932px`，所有场景视觉物件（含硬投影）止于 `y=912px`。
- [ ] 每条字幕只有 0–1 个经过语义核对的对象色关键词；高亮保持可访问对比度、没有逐词动画或叠加强调。
- [ ] 文字层级遵守字号下限，卡片文字可在一遍播放中读完；没有用缩小字体补救过长文案。
- [ ] 卡片内所有中文语义文字至少为 `30px / 700`；对象名、规则、关键词和结果至少为 `40px / 800`。`20px` 等宽字只出现于不影响理解的元数据，未被用于知识内容。
- [ ] 窗口、便签、角色卡和关系线确实说明一个完整关系，而不是网页组件拼贴。
- [ ] 每条关系线符合 5.2.1 的两套语法之一；线层在节点、文字和硬投影下方，端点与组件描边/投影至少保持 `8px` 间隙，没有遮挡、断连或突兀的大箭头。
- [ ] 对每条带箭头的流程线，检查“目标节点出现前、路径绘制中、路径完成后”三帧：箭头只能随路径开始出现，任一帧都没有无来源、无目标或悬空的箭头。
- [ ] 真实素材保持事实可辨，覆盖层只标注已核对对象；未出现伪造 UI 或未经授权的原片元素。
- [ ] 进入、连接、锁定和停留的顺序与旁白关系一致；播放过程与关键静帧都可读。
- [ ] 屏显术语、字幕高亮和画面对象没有与当前旁白冲突，也没有提前泄露后段机制或数量；同名对象跨画面/字幕使用同一语义色。
- [ ] 每个关键关系都有声明的证据类型；程序化纸面图没有冒充真实产品、数据或录屏。
- [ ] 实现中的文案、cue 时间和终态已与项目的音画契约逐项核对。
- [ ] 关系拓扑先于布局得到确认：CONNECT 从源端描边外缘接到目标端描边外缘，等权 hub-and-spoke 已均衡或已声明不对称理由，decision fork 的回路和风险说明归属对应分支。
- [ ] 状态色只在叙述到位后切换；RESOLVE 的 Blue 方案卡与 Mint 状态徽章按先后出现，文字始终在覆盖层之上可读。
- [ ] 每个纸片动作都对应 7.2 的一个命名动词；同一动作没有同时承担两个动词语义，HOLD 终态没有被转场代替。
- [ ] 每个 DIM 均声明轻/中/强等级；仍有解释价值的纸片没有被强 DIM，被 DIM 的 Orange 问题卡仍能被辨认为问题，终态人工可读。
- [ ] 动作、字幕锚点、最终音频/SRT 与项目 beat registry 的 cue 对齐；跨 cue 的顺序变化已逐项记录。
- [ ] 项目已引用独立的项目视觉适配合约，并在其中记录项目专属色彩叙事、关系拓扑、逐 cue 事件及自动/人工验收。
