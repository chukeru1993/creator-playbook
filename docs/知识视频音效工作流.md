# 知识视频音效工作流

本仓库收录的是让 Agent 为知识视频执行语义音效 Spotting 的方法，而不是一个可公开分发的音频素材包。音效的职责是帮助观众定位关系、感知状态改变、确认结果或注意风险；它不应为每个动效制造存在感。

对于 AI Agent、编程和开发工具画面，优先采用 `developer_ui_feedback`：一声对应一次可见且可解释的状态迁移。代码逐字输入、光标闪烁、终端滚动、普通卡片进场和装饰性 UI 动作默认静音。

## 资产边界

| 位置 | 职责 | 是否属于本仓库 |
| --- | --- | --- |
| [skills/knowledge-video-sfx/](../skills/knowledge-video-sfx/) | 事件分类、cue 格式、模板与校验脚本 | 是 |
| 外部 `sfx-catalog.yaml` | 共享音频素材的语义索引、技术特征、来源和使用边界 | 否，由使用者维护 |
| 外部原始音频文件 | 被 catalog 索引的可授权素材 | 否，由素材库管理 |
| 项目 `sfx-cues.yaml` | 当前视频的候选、试听状态、视觉/旁白锚点和时间码 | 否，留在视频项目 |
| 项目 `sfx-spotting.md` | 供人工审阅的重点 cue、静音决定和素材缺口 | 否，按项目需要创建 |

这也是原 `soundeffect/` 目录不应保留的原因：它没有包含 catalog 或音频，却用 README 声称自己是“音效库”。当前最准确的位置是 `docs/`，作为方法与外部素材库的契约说明。

若未来确实要发布独立音效库，应建立一个真实、可审计的资源目录或独立仓库，至少包含 `sfx-catalog.yaml`、素材来源与许可记录，以及所有实际提交的音频文件。确认每个素材都可按仓库许可证再分发之前，不要将音频复制进本仓库。

## 使用流程

1. 完整安装或复制 [knowledge-video-sfx](../skills/knowledge-video-sfx/) 目录，并向 Agent 提供口播稿、字幕、分镜、动画描述或合成源，以及可访问的 `sfx-catalog.yaml`。
2. 先判断声音是否有定位、因果、确认、风险或结论作用。没有明确认知职责的动作记录为 `omissions`，不要建立 cue。
3. 将语义事件、可见动作和旁白依据写入项目 `sfx-cues.yaml`。没有最终音频、SRT 或已实现时间线时，`timing.at_s` 保持 `null`，以视觉/旁白锚点定位，不根据口播估时伪造秒数。
4. 从 catalog 的 `use_for`、`avoid_for`、材料、能量、亮度和时长中匹配候选；不要根据文件名猜测音效意义。运行结构校验，例如从本仓库根目录执行：

   ```bash
   ruby skills/knowledge-video-sfx/scripts/validate_sfx_cues.rb \
     --catalog /path/to/shared/sfx-catalog.yaml \
     --cues /path/to/project/sfx-cues.yaml
   ```

5. 在包含旁白、字幕和动画的目标镜头中试听。`preferred` 是素材库的优先试听标记，`selected` 是项目的默认选择；两者都不是批准。只有试听通过的 cue 才能标为 `approved` 并进入最终合成。

事件分类、字段格式和模板分别以 [event-taxonomy.md](../skills/knowledge-video-sfx/references/event-taxonomy.md)、[sfx-cues-format.md](../skills/knowledge-video-sfx/references/sfx-cues-format.md) 和 [sfx-cues.template.yaml](../skills/knowledge-video-sfx/assets/sfx-cues.template.yaml) 为准。

## 密度与静音

先根据可见的语义动作密度选择 `sparse`、`balanced` 或 `dense`，再用目标区间检查是否遗漏了重要状态迁移。`balanced` 通常是每分钟 3.5-5.0 条 `needs_audition` 或 `approved` cue，但这只是覆盖复查线，不是填满每次动画的配额。

连续 20 秒内若出现两个以上新的、重要且离散的状态迁移，却没有任何 cue，应补最强的一个候选，或记录此段静音理由。普通物体运动、重复进入和装饰动画不算状态迁移；一个长场景可以有多个 cue，但它们必须承担不同的认知职责，通常至少相隔 3 秒。

## 共享素材库维护

`sfx-catalog.yaml` 是素材语义的唯一来源。每个可用素材应记录稳定 `id`、实际 `file`、`tags`、`material`、`energy`、`brightness`、`duration_ms`、`use_for`、`avoid_for`、状态、内容哈希，以及可核查的来源、作者、下载日期和许可信息。

新增素材时，保留原始文件，先检查授权和内容哈希，再分析其起音、尾音、时长与信号特征。新条目先标为 `candidate` 或 `review_required`，在具体镜头中证明其可复用后才升为 `preferred`。单个项目缺少合适声音时，先在该项目的 cue 表标记 `blocked`；只有多个项目稳定出现同一缺口，才扩展共享库。

| catalog 状态 | 含义 |
| --- | --- |
| `preferred` | 适合优先试听的素材，不代表项目已批准 |
| `candidate` | 语义可能适合，必须结合镜头试听 |
| `sparing` | 过重、过长或强调性强，只用于少数结论或大转折 |
| `review_required` | 不得自动应用，需人工判断是否符合知识视频语法 |
| `duplicate` | 与另一文件内容相同的保留别名，不作为新候选 |

结构校验可以验证字段、候选和密度，不能替代创作判断。每次正式使用仍应检查起音、落点、尾音、旁白遮挡和连续提示声的疲劳感。
